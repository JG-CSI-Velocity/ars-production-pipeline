Operational Intake Process

1. ReceiveClient sends monthly account, transaction, and support files.
2. ProfileDetect delimiter, headers, row counts, source family, and contract match.
3. DecideUse, hold, review candidate layout, or ask for a replacement extract.
4. AssembleSelect account and transaction inputs for the engine run.
5. ContractPromote existing contracts or create/edit client-specific YAML drafts.
6. LoadStage selected files and generated outputs to Snowflake targets.
7. ClearResolve intake, mapping, metric, and client-use blockers from the backlog.
CSM

Confirm which files the client sent, request missing layouts, and document whether fallback extracts such as modified ODD can be used.

Analyst

Review candidate layouts, unresolved fields, and whether analysis caveats must be attached before client-facing use.

Data / Snowflake

Promote contracts, load selected files, validate row counts, and clear target-table blockers before production use.
